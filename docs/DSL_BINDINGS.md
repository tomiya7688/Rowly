# Rowly DSL の変数・定数・再代入

この日本語文書を Issue #53 の宣言・束縛・スコープ仕様の正本とする。DSL 全体の 1.0 仕様凍結は Issue #55 の別実装単位であり、本変更で完了したことにはしない。

## 宣言と再代入

```text
VAR count = Integer("0")
CONST increment = Integer("2")
count = count + increment
```

`VAR name = expression` は再代入可能な名前を宣言する。`CONST name = expression` は初期化後に再代入できない名前を宣言する。どちらも初期値が必須であり、初期化式は宣言に到達した時点で1回評価する。`CONST` はコンパイル時定数を要求せず、関数の戻り値やオブジェクトも受け取れる。

再代入は `name = expression` とする。未宣言の名前を暗黙作成しない。キーワードと識別子の英字部分は従来どおり ASCII の大文字・小文字を区別せず、`VAR` / `CONST` の直後の空白・タブを許可する。識別子は既存規則どおり、先頭が文字または `_`、後続が文字・数字・`_` である。日本語の識別子も利用できる。

`Self`、`Super`、`true`、`false`、`VAR`、`CONST`、`LET`、`DIM`、`Text`、`Number`、`Boolean` は変数、引数、ループ変数の名前に使えない。`Text` / `Number` / `Boolean` は 1.0 標準関数の名前空間として予約する。`Self` の代入による差し替えも構文エラーとする。`Self.value = ...` など既存フィールドの編集は別の操作である。

## 値の型

本変更は宣言の可変性を追加するもので、リテラルや CSV の型推論を変更しない。従来どおり数値演算には `Integer(...)` / `Decimal(...)`、真偽値には `Boolean(...)` の明示変換を使用する。

例えば `VAR count = 0` の `0` は既存の文字列リテラルとして保持される。整数の加算を行う場合は `VAR count = Integer("0")` と書く。`CONST text = "001"` は先頭のゼロを保持する。`VAR` の再代入時も暗黙変換をせず、右辺で得たランタイム値をそのまま受け取る。

## スコープ

宣言は現在のスコープへ新しい束縛を作る。同一スコープで同じ名前を再宣言することは、`VAR` / `CONST` の組み合わせを問わずエラーとする。これにより `CONST` を再宣言して可変性を変更する抜け道を作らない。

内側スコープでの宣言は、外側の同名束縛を隠してよい。その場合も外側の値や可変性は変わらない。初期化式の評価中はまだ新しい束縛を登録していないため、同名の外側の値が見える場合はそれを参照できる。見える値がなければ自己参照も未宣言エラーになる。

再代入は、現在見えている最も内側の束縛を探して更新する。内側に同名宣言がなければ外側の `VAR` への明示的な再代入も可能だが、外側が `CONST` ならエラーになる。従来の呼び出し時スコープ探索を維持し、クロージャや新しい静的スコープ解決方式は導入しない。

### 関数・メソッド・コンストラクタ

関数、メソッド、`Init` の呼び出しごとに新しいローカルスコープを作る。引数は可変のローカル束縛であり、値を入れ直す場合は `value = ...` と書く。同名引数を `VAR` / `CONST` で再宣言しない。

ローカル宣言は終了時に破棄し、外側へ漏らさない。`Return` や実行エラーで終了する場合もスコープを取り除く。継承と `Super` の呼び出しでも同じ規則を適用する。メソッド実行時の暗黙の `Self` は再代入不能な束縛とし、元のオブジェクトを指し続ける。

### If / Else

`If` / `Else` は既存のスコープを共有し、新しいスコープを作らない。実行された分岐で宣言した変数は、そのスコープの残りの処理から見える。実行されない分岐では宣言・初期化を行わない。ただし削除された構文などの構文エラーは、実行されない関数や分岐の中でも解析時に検出する。

### For / Next

各反復に新しいスコープを作り、ループ変数と反復内の `VAR` / `CONST` をそこへ置く。反復終了時に破棄するため、ループ内で毎回 `CONST current = row` と書いても同一スコープでの再宣言にはならない。反復間でローカル値を引き継がず、ループ終了後も外側へ漏らさない。ネストしたループも同じ規則に従う。

```text
VAR total = Integer("0")
For row = Integer("2") To RowCount()
    CONST score = Integer(CellValueByHeader(row, "Score"))
    total = total + score
Next row
```

集計など反復をまたいで保持する値は、ループの前に宣言する。旧実装の反復間でのローカル値の残存に依存した処理は、この形へ移行する。開始値・終了値・Step の評価回数と数値ループの進行規則は変更しない。公開されたループ変数への代入は当該反復内の値だけを変え、次の反復を決める内部カウンタは変更しない。

## CONST とオブジェクト

`CONST` は名前の再束縛だけを禁止し、参照先のフィールドを再帰的に凍結しない。既存のオブジェクト同一性と別名参照を維持する。

```text
Class Box
    Field value = "initial"
End Class

CONST box = New Box()
VAR alias = box
alias.value = "updated"
VAR current = box.value
```

この例で `current` は `updated` になる。`box = New Box()` は定数への再代入エラーになるが、`box.value = ...` やメソッド経由の変更は禁止しない。オブジェクトそのものを CSV セルへ書くことは従来どおり禁止する。

## エラーと副作用

未宣言名への再代入は `ExecutionError::UnknownVariable`、定数への再代入は `ConstantAssignment`、同じスコープでの再宣言は `DuplicateVariable` として報告する。対象の存在・可変性・再宣言を右辺の評価より先に検証する。

したがって禁止された `fixed = TouchCsv()` では `TouchCsv()` を呼ばない。ただし、右辺そのものが途中で失敗した場合や、それ以前の文で完了した CSV 編集を自動的に巻き戻す変更ではない。CSV 編集と履歴は既存の process API を使い、transaction の開始・commit・rollback も既存の明示操作に従う。変数宣言や再代入自体では CSV の内容・保存形式・dirty 状態を変更しない。

## 旧構文からの移行

旧 `LET` / `DIM` 宣言は大小文字を問わず構文エラーにする。文字列やコメントの中の同じ文字列は変更しない。

新しい名前の作成は `VAR name = value`、再代入不要なら `CONST name = value` に置き換える。同じスコープで繰り返していた値の入れ直しは、2回目以降を `name = value` にする。既存引数への値の入れ直しにも宣言キーワードは付けない。

Rust API では旧 `Statement::Let` を削除し、`Statement::Declare { kind, name, value }` と `Statement::Assign { name, value }` に分離する。`DeclarationKind` は DSL モジュールから公開する。`ExecutionEvent::VariableSet` は宣言と再代入の双方で従来どおり生成する。

## 検証対象

専用テスト `src/rowly_dsl/tests_bindings.rs` で、AST、大小文字と空白、再代入、定数保護、右辺の副作用防止、重複宣言、ローカルと引数、外側の束縛、反復と Return、継承とコンストラクタ、別名参照、旧構文拒否、予約名、未初期化参照を検証する。既存の全 DSL テストも新しい宣言構文へ移行し、算術・条件・セル操作・履歴などの回帰を継続確認する。

名前空間付き標準関数への移行、全言語仕様の凍結、GUI は本実装単位には含めない。
