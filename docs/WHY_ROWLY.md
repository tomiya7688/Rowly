# 何故Rowly？

> **CSVを正本のまま、表計算ソフトの使いやすさを得たい。**

Rowlyは、そのために作っています。

Excelは非常に強力です。  
表を作る、計算する、並べ替える、絞り込む、見やすくする。多くの人が表データを扱うときに期待する操作を、長い年月をかけて磨いてきました。

Rowlyも、その使いやすさから学びます。

しかし、RowlyはExcelのデータモデルをそのまま真似しません。

## CSVは、ただの途中形式ではない

Rowlyでは **CSVそのものを正本** とします。

CSVは単純です。

- 普通のテキストとして読める
- Gitやdiffで比較できる
- Python、Rust、R、シェル、データベースなど、多くの道具から扱える
- Rowlyがなくてもデータを回収できる
- 別のアプリで編集しても、同じデータであり続ける

この単純さは欠点ではなく、強い性質です。

Rowlyは、便利な機能を増やすためにこの性質を失いたくありません。

## データと、計算と、見た目を混ぜない

表計算ソフトでは、一つのセルの中に値・式・表示状態が混ざりやすくなります。

Rowlyでは、それぞれを分けます。

```text
Edit  = 式・規則・割当を編集する
View  = 評価した答えを見る
Code  = CSV正本の生テキストを見る / 直接編集する
```

たとえば計算式をセルへ割り当てることはできます。

しかし、CSVセルの値を `=B2*C2` のような式そのものにはしません。  
計算規則はCSV外のCalculation Bindingとして持ち、Viewではその答えを表示します。

答えをCSVへ確定したいときだけ、明示的にMaterializeします。

**式はEdit。答えはView。正本はCode。**

この分離によって、「今見えているもの」と「実際に保存されているデータ」を区別できます。

詳細は [CSV・計算・表示の設計原則](DATA_MODEL_PRINCIPLES.md) を参照してください。

## 見た目のためにデータを壊さない

連続する同じ値を、一つのセルのように見せたいことがあります。

Rowlyでは、それをViewの仕事にします。

```text
CSV
東京
東京
東京
```

を、Viewでは一つのまとまりとして表示できます。

しかし、そのためにCSVを

```text
東京


```

へ書き換えることはしません。

**データは結合しない。見た目だけをまとめる。**

表示設定をすべて捨てても、元のCSVが完全に残ることを重視します。

## Rowlyだけが世界の中心ではない

CSVは、Rowly以外のアプリから編集されることを前提にします。

外部エディタ、スクリプト、生成処理、Git、他のCSVツール。  
それらがRowlyを開いている間にCSVを書き換えることも、異常な使い方とは考えません。

Rowlyはファイルを囲い込むのではなく、外部変更を検知し、競合を扱い、Rowly側の変更も失わないようにします。

Rowlyの世界は閉じたworkbookではなく、普通のファイルと共存する作業環境です。

## GUIだけを特別扱いしない

Rowlyの操作は、できるだけ一つのCommand境界へ集めます。

```text
GUI
Rowly DSL
CLI
Luau
   ↓
Command / process
   ↓
CSV
```

GUIにしか存在しない秘密の操作を増やしたくありません。

人がマウスで行った操作も、キーボードで行った操作も、DSLで自動化した操作も、CLIから実行した操作も、可能な限り同じ意味を持つべきです。

だからRowlyは **keyboard-first** であり、同時に **automation-friendly** でもあります。

## Excelを真似ないことと、Excelより不便であることは別

Rowlyは、Excelの操作性まで捨てたいわけではありません。

セル選択、範囲選択、コピー、貼り付け、検索、置換、Sort、Filter、Undo / Redo、キーボード操作。  
こうした表計算ソフトとして当たり前の使いやすさは、きちんと実装します。

捨てたいのは、便利さではありません。

- 式をデータそのものへ埋め込むこと
- 見た目のために値を失うこと
- 一つの独自ブック形式へデータと状態を閉じ込めること
- GUIだけに操作を隠すこと
- 外部編集を敵として扱うこと

そうした設計です。

## XLSXは必要。でも正本にはしない

現実の仕事ではXLSXとのやり取りが必要です。

だからRowlyはImport / Exportを重視します。

ただし、XLSXを第二の正本にはしません。  
外部形式との橋として扱い、Rowlyの中心には常にCSVを置きます。

## Rowlyがなくても、データは残る

Rowlyのプロジェクト設定、View設定、Calculation Binding、履歴、自動化は、作業を便利にするためのものです。

それらは大切です。

しかし、それらが無ければデータを読めない、という状態にはしたくありません。

Rowlyをアンインストールしても、プロジェクト設定を失っても、CSVそのものは普通のCSVとして残る。

それがRowlyの最も重要な約束です。

---

Rowlyは、CSVの単純さを捨てずに、表計算ソフトの使いやすさ・安全な履歴・自動化・プロジェクト管理を重ねることを目指します。

**Excelを再実装するのではなく、Excelを開く必要そのものを減らす。**

それがRowlyです。
